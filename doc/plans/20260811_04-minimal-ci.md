# Plan: Minimal Continuous Integration

## Summary

Add one bounded GitHub Actions job that runs the repository's existing Go,
browser, formatting, and purity checks on pushes to `main` and pull requests.
Use maintained official setup actions and the versions already owned by the
repository; add no new test framework, linter, package manager, or release
automation.

## Problem

The repository has strong, inexpensive local tests but no checked-in CI
workflow. A pushed commit can therefore reach the shared branch without any
repository-controlled verification. The deterministic-time cleanup makes the
complete browser suite cheap enough to run on every change.

## Scope

In scope:

- One GitHub Actions workflow with one Ubuntu job for pull requests and pushes
  to `main`.
- Read-only repository permissions and a ten-minute job timeout.
- Go setup from `go.mod` and a single current Node release for the built-in
  browser tests.
- Run formatting, Go tests, Go vet, the pure-module boundary check, and the two
  Node test files.
- Document CI as the automatic runner of the existing testing layers.

Out of scope:

- Operating-system or runtime matrices, coverage thresholds, badges, release
  builds, deployments, branch-protection changes, or live Spotify tests.
- Third-party linters, `actionlint`, npm metadata, dependency bots, or a new
  repository check script.
- Production configuration, remote-server work, or deployment verification.

## Design

Create `.github/workflows/check.yml` with a single `checks` job on
`ubuntu-latest`, `permissions: contents: read`, and `timeout-minutes: 10`.
Use the maintained major releases of the official checkout, setup-go, and
setup-node actions at implementation time. Configure setup-go with
`go-version-file: go.mod`; use the documented Node 18 minimum for the
dependency-free test harness and do not enable a package-manager cache.

Run only nonredundant repository checks:

1. Fail when `gofmt -l .` reports a Go file.
2. Run `go test ./...`.
3. Run `go vet ./...`.
4. Apply the documented inverse grep that keeps platform names out of
   `web/pure.js`.
5. Run `node --test web/pure_test.js web/app_test.js`.

The Node suite loads both production scripts, so separate `node --check`
invocations add no coverage in CI. `git diff --check` against an untouched
checkout likewise adds no useful signal. Keep local commands available for
focused work; CI is a verifier, not a new task runner.

## Affected Components

- `.github/workflows/check.yml`: define the single bounded verification job.
- `doc/architecture/testing/TESTING_MODEL.md`: record where the existing test
  layers run automatically and update its revision date.

## Implementation Sequence

Execute after the deterministic browser-test-time plan, then:

1. Add the workflow with minimal permissions, runtime setup, timeout, and
   existing checks.
2. Update the testing model without duplicating the YAML.
3. Run the same commands locally, push through the normal repository workflow,
   and confirm the triggered job succeeds.

## Validation

```sh
test -z "$(gofmt -l .)"
go test ./...
go vet ./...
! grep -nE 'document|window|fetch|localStorage|sessionStorage|crypto|location|history' web/pure.js
node --test web/pure_test.js web/app_test.js
git diff --check
```

Inspect the workflow permissions, triggers, action majors, and timeout before
push. No live external account is used.

## Success Criteria

- Pull requests and pushes to `main` trigger exactly one bounded checks job.
- The job selects Go from `go.mod`, runs the existing browser suite on Node 18,
  and requires no package installation.
- Formatting, compilation/tests, vet, the pure-module boundary, and browser
  behavior all gate success.
- The first triggered run is green, and no deploy, release, coverage, or
  third-party tooling has been introduced.
